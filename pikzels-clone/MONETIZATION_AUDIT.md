## Pending: Face Swap Usage Enforcement

The `faceSwap` field in `subscription.config.ts` now defines per-tier limits:

| Tier              | Face Swaps     | Credits |
| ----------------- | -------------- | ------- |
| Free              | 3              | 5       |
| Starter ($9/mo)   | 10             | 30      |
| Pro ($24/mo)      | 50             | 120     |
| Business ($79/mo) | Unlimited (-1) | 500     |

**Current state:** The `requireFeature('faceSwap')` middleware gates access (truthy check), but there is NO per-period usage counter enforcing the numeric limit. Credits provide a natural ceiling (free users can't exceed 5 total operations), but dedicated face swap counting is not yet implemented.

**What's needed:**

- Database field or table to track face swap usage per user per billing period
- Reset logic tied to billing cycle (monthly)
- Service-layer check: compare usage count against plan's `faceSwap` value
- Handle `-1` (unlimited) for Business tier
- Return clear error with current usage vs limit when exceeded

## Planned Feature: Camera/Selfie Capture for Face Swap

### Research Summary (March 2026)

No web-based thumbnail/face-swap SaaS competitor implements in-browser webcam capture. Live camera capture exists only in native mobile apps (Snapchat, Face Swap Live) where camera access is a core OS feature.

| Competitor        | Platform   | Face Input Method           | Browser Webcam? |
| ----------------- | ---------- | --------------------------- | --------------- |
| Pikzels           | Web        | File upload                 | No              |
| ThumbnailFace.app | Web        | File upload                 | No              |
| Reface            | Mobile app | File upload (camera via OS) | N/A             |
| AISWAPR           | Web        | File upload                 | No              |
| Snapchat          | Mobile app | Live camera                 | N/A (native)    |
| Face Swap Live    | Mobile app | Live camera                 | N/A (native)    |

### Why Web Competitors Skip Webcam Capture

- Mobile browsers already offer "Take Photo" via `<input type="file" accept="image/*">` (OS file picker)
- Desktop webcam quality (720p) is inferior to phone camera photos users already have
- Browser webcam introduces permission prompts, UX complexity, and privacy concerns
- Users typically have selfies readily available in their device gallery

### Recommendation

**Low priority.** The existing `<input type="file" accept="image/*">` already provides camera capture on mobile via the native OS file picker. Adding browser `getUserMedia()` webcam capture would only benefit desktop users who want to take a photo on the spot -- a narrow use case for thumbnail creation.

If implemented later, it would be a ~30-40 line addition using `navigator.mediaDevices.getUserMedia()` as an optional "Take Photo" button alongside the existing upload drop zone in the face modal. No tier gating needed -- it's just an alternative input method, not a premium feature.

### Implementation Notes (for future reference)

- Use `navigator.mediaDevices.getUserMedia({ video: { facingMode: 'user' } })`
- Render to `<video>` element, capture frame to `<canvas>`, export as data URL
- Add as secondary option in existing face modal (DashboardHome.tsx lines 708-818)
- Feature detection: check `navigator.mediaDevices` before showing button
- No backend changes needed -- same base64/file flow as upload
